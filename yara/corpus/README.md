# YARA corpus

`yara/ghost_implant_structural.yar` compiled, and that was the whole proof it
worked: compiling is a syntax check, not a false-positive measurement. The
gap register called this out - "nothing proves it matches a build or stays
quiet on real software".

This directory is the corpus, and it is **not committed**. The files are
generated by `tools/build_yara_corpus.py`, which is deterministic (no clock, no
random seed), so the same command produces the same bytes anywhere. Keeping them
out of git is deliberate: this repository's defensive-only claim includes "no
binary artifacts in git" (`tests/test_scope.py`), and a committed `.bin` would
break that promise to prove a smaller one.

`yara/corpus/README.md` is committed; the files it describes are not. The gate
regenerates them before the YARA tests run.

## What is here

| Directory | Contents | Expected |
|---|---|---|
| `implant/` | a synthetic stand-in for the implant shape: a PyInstaller-style PE stub carrying an AMSI patch, an ETW patch, a `_MEI` path, a beacon header pair and a DGA seed | **must match** |
| `benign/` | ordinary software shapes that carry *some* of the same strings | **must not match** |
| `partial/` | one indicator at a time, plus pairs that are not evidence | **must not match** |

`benign/` is the half that had no test before. Each file there is built to
contain a plausible subset of the implant's strings - because real software
does:

| Benign file | Why it carries the string | Rule must stay quiet because |
|---|---|---|
| `msmpeng_like.bin` | a security product embeds `AmsiScanBuffer` (it *calls* it) | one evasion symbol is not a patch: the patch bytes are absent |
| `edr_etw_consumer.bin` | an ETW consumer names `EtwEventWrite` | same: naming a function is not overwriting it |
| `python_embed.bin` | a legitimate PyInstaller app has `_MEI` and `python3.dll` | `_MEI` alone is not a header pair |
| `browser_update.bin` | a browser ships `X-Id` in an internal header enum | one header of the pair is present |
| `uptime_agent.bin` | a monitoring agent has a `PSK` field name and a `DGA_SEED` comment | two strings that appear together in benign code |
| `installer_signed.bin` | an installer references `svc_update.exe` | `autorun.inf` is absent |

## Reproducing

```bash
python3 tools/build_yara_corpus.py            # (re)build the files
python3 tools/build_yara_corpus.py --check    # fail if any file is stale
```

The generator is deterministic: the same bytes every time, no clock, no random
seed. `--check` is still meaningful - it catches a hand-edited corpus file or a
generator change - and the tests assert determinism directly rather than
trusting the claim in this paragraph.

## What this corpus is not

It is not a sample of real malware, and it is not a benign-software benchmark.
Six synthetic files cannot measure a false-positive rate; they can only prove
the rule's *logic* is not trivially wrong in the six ways that matter most.
Real precision still requires a corpus the lab does not have, which stays open
as a gap rather than being papered over by a green check.
