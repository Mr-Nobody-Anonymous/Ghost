# Fixtures

A fixture is a description of expected telemetry, not a payload. No fixture in
this folder executes code or contains a working exploit.

## per_rule/ and negative/

One JSON file per rule, named by the rule's UUID:

- `per_rule/<id>.json` - events that must make the rule fire, plus the field
  values the alert has to carry.
- `negative/<id>.json` - a concrete event that must NOT make it fire, plus the
  benign software classes it resembles.

Both are generated by `tools/generate_fixtures.py` from the rule's own detection
block, then verified by the evaluator - a fixture that the rule does not
actually match is a failing test, not a pass. Generated fixtures are
`status: designed`: they prove the rule is internally consistent and that its
field names and paths could come off a real host. They do **not** prove
detection. Only a capture from a pinned sample does, and no capture exists yet
(see `docs/maturity.md`).

```bash
python3 tools/generate_fixtures.py            # regenerate
python3 tools/generate_fixtures.py --check    # fail if any fixture is stale
python3 detection-as-code/evaluate.py         # TP/FP/sequence/frequency
```

A correlation fixture carries its member rules inline under `members`, because a
correlation cannot be evaluated unless its members resolve in the same
collection.

## benign/

The false-positive corpus specification. Each entry names a legitimate software
class, the events it produces, and the tuning decision that keeps the rules
quiet. Nothing here has been executed; the corpus is a plan, not a result.

## Rules

- A rule is not "covered" until both a positive fixture passes and the benign
  corpus is clean.
- Fixtures reference rules by `rule_id`, never by path.
- If telemetry changes, regenerate the fixture; never hand-edit observed values
  to make a test pass.
- A fixture value must be something a host could actually emit: registry keys
  are registry keys, URIs are URIs, and `.bmp` is not a directory name. The
  generator enforces this through `detection-as-code/fieldtypes.py` and the test
  suite checks it.
