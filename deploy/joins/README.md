# Generated cross-platform joins

`ci/convert_check.py` records `elastic: unsupported` and `kusto: unsupported` on
every correlation rule, because pySigma 1.x converts correlations only through
the Splunk backend. Before this directory existed, that meant a user on Elastic
read five `unsupported` lines and a Markdown specification, and had to write the
join themselves.

These files are generated by `deploy/build_joins.py` from the rule YAML and its
members' detection blocks, so they cannot drift from the rules. `ci/gate.sh`
regenerates them with `--check` and fails on a stale file.

| File | Language | What it is |
|---|---|---|
| `*.eql` | Elastic EQL | `sequence by <key> with maxspan=<window>` for the two `temporal` correlations |
| `*.esql` | Elastic ES\|QL | threshold (`STATS ... BY ... \| WHERE events >= n`) for the two `event_count` correlations |
| `*.kql` | Kusto | the same join expressed with `union` + `summarize` + an order check for sequences, `bin()` + `count()` for thresholds |

## What is guaranteed and what is not

Guaranteed, because a test asserts it: the queries are regenerated on every gate
run, the boolean structure of each member's condition is preserved with explicit
parentheses, `|exists` becomes a null check rather than a literal string, and a
modifier the target language cannot express is a hard failure rather than a
loose approximation.

Not guaranteed: that these run correctly against a real cluster. Nothing in this
repository has been executed against Elastic or Kusto. `ES|QL` and `EQL` both
change between minor versions, and the field names in `deploy/build_joins.py`
(`process.executable`, `dns.question.name`, `SrcIpAddr`, ...) are the names this
repository documents in `telemetry/data-sources.md`, not names read back from a
live index template.

## Where a language has no equivalent

EQL has no regex. `dga_high_entropy_dns` and `dns_query_burst_host` both select on
`|re`, so their *threshold* form is ES|QL (which has `RLIKE`) and Kusto (which
has `matches regex`). If a future `temporal` member uses `|re`, the generator
exits 1 rather than emitting a `LIKE` that matches a much wider set - the exact
defect this repository exists to stop repeating.
