# Python Interpreter Spawning Shell or Task Tools

- Rule: `1a2b3c4d-5e6f-4708-9a0b-1c2d3e4f5a07`
- Severity: medium
- ATT&CK: T1059, T1053.005
- Tactic: execution
- Status: **drafted from the rule, not worked against a live alert**

## What fired

pythonw.exe or a PyInstaller child spawning cmd.exe, powershell.exe, schtasks.exe or net.exe. The parent is taken from Sysmon's ParentImage, which records the full path, so the previous `\pythonw.exe` and `\_MEI` literals could never match; both are now path predicates.

Event IDs in scope: 1.

## Triage

Check these in order. The first one that is empty means the rule matched on a field the collector did not populate.

- `EventID`
- `Image`
- `ParentImage`
- `ParentCommandLine`

Read the parent process before the command line. The command line tells you what ran; the parent tells you who chose it.

## Containment

`kill-process` - Stop the process by PID after capturing the image. Then check what its parent did, because the parent chose it.

Do not close out on the containment action alone. The entry being removed does not answer how it got there.

## What to preserve

- The full command line, not the truncated display form
- The parent process and its command line
- Any script file the command referenced, with its hash

## When this is a false positive

IT automation runs PowerShell and WMI on managed hosts. The discriminator is the execution context: a management tool's signed binary and a service account, not `explorer.exe`.
