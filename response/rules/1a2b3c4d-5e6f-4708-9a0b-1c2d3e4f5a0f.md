# Self-Deleting Executable

- Rule: `1a2b3c4d-5e6f-4708-9a0b-1c2d3e4f5a0f`
- Severity: high
- ATT&CK: T1070.004
- Tactic: unmapped
- Status: **drafted from the rule, not worked against a live alert**

## What fired

A process deletes its own image file, consistent with a kill-switch cleanup or an unpacks-and-removes dropper. The image path is compared to the deleted file with Sigma's `fieldref` modifier so no per-sample path is hard-coded. The original draft used Sysmon event ID 23, which Sysmon never emits; FileDelete is event 26 in Sysmon 13+ and derives from EID 11.

Event IDs in scope: 26.

## Triage

Check these in order. The first one that is empty means the rule matched on a field the collector did not populate.

- `EventID`
- `TargetFilename`

Check each field for presence before checking its value. A missing field means the collector never populated it, and a rule matching on nulls is quiet rather than empty.

## Containment

`isolate-host` - Isolate the host pending a decision that needs no further telemetry.

Do not close out on the containment action alone. The entry being removed does not answer how it got there.

## What to preserve

- The alert's raw event, verbatim, before any field is normalised
- The host's clock offset from the collector
- The rule version that fired, from the rule's own id

## When this is a false positive

The behaviour this rule matches has legitimate causes on a managed host. Before closing, identify the parent process and whether the binary is signed; a signed path under `Program Files` with a service-account parent is the ordinary case.
