## First triage step

A process created an executable or `autorun.inf` on a non-`C:` volume. The
signal is deliberately weak: installers, portable-app deployment and backup
tools all do this, and Windows 10 1703+ ignores AutoRun for USB sticks, so the
`autorun.inf` half is largely historical.

1. Identify the writing process (`Image`) and the volume. A removable stick
   mounted in the last few minutes raises this materially; a second internal
   disk does not.
2. Check whether the same process created the executable *and* a compliant
   `autorun.inf` in the same window. The pair is the spreader shape; either
   alone is common.
3. Correlate with `autorun_inf_writes.yml` and, if available, device-arrival
   telemetry (`DriverFrameworks-UserMode` 2003) which this repo does not collect.
4. Record the decision in `docs/tuning-log.md` (allowlist / threshold / retire / keep).
