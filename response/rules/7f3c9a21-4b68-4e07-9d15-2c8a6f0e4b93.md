## First triage step

At least three of four chains fired for the same host inside one hour: CPU
key read -> security component tamper, WMI subscription create/filter/consumer/binding,
a beacon by request frequency, or a DGA NXDOMAIN burst.

1. Establish which three fired and in what order. The report prints the labels;
   order matters less than co-occurrence, but a host that tampered *before*
   recon is usually an agent restart rather than an intrusion.
2. Confirm the host in question was not mid-reimage, mid-SCCM-repair, or in a
   red-team window. The campaign rule has no allowlist for either, by design:
   three chains in an hour is worth a human's two minutes even when benign.
3. Pull the process tree for the tamper chain. That is where the operator's
   binary appears; the campaign alert exists to tell you to go look.
4. Record the decision in `tuning/observations.csv` via
   `tools/tuning_log.py --render`.
