# Implant Campaign - Recon, Tamper, Persist, and Egress in One Window

- Rule: `7f3c9a21-4b68-4e07-9d15-2c8a6f0e4b93`
- Severity: high
- ATT&CK: T1497, T1685, T1546.003, T1071.001
- Tactic: discovery
- Status: **drafted from the rule, not worked against a live alert**

## What fired

A cross-source campaign correlation. The five existing correlations each prove one ordering inside one data source; none of them says "this host did recon, then tampering, then persistence, then talked to the internet inside one hour". That shape is what separates an implant that got somewhere from a tool that ran once, and no single-event rule can express it.
The rule is deliberately built out of four *chains*, each of which is itself a sequence or threshold, and a condition that requires at least three of the four to have fired. Requiring all four would be a rule that only fires on a complete, textbook intrusion; requiring three keeps it honest about the fact that an operator who skips a stage is still an intrusion.
This is a `1 of` across correlation members rather than a `temporal` across single events because the members have different natural join keys (a Python child process, a WMI subscription triple, an L2-encrypted beacon). Forcing them onto one shared field would be the `ProcessId`-in-a-4663-rule defect this repository already fixed once. Grouping is therefore by `Computer`, which every member carries.

Event IDs in scope: none.

## Triage

Check these in order. The first one that is empty means the rule matched on a field the collector did not populate.


Enumeration is usually the quiet step before a loud one. Look for what the same process did next, not at the enumeration.

## Containment

`isolate-host` - Enumeration alone is not damage, so isolate rather than erase: the value of this alert is the next step it predicts, not the enumeration itself.

Do not close out on the containment action alone. The entry being removed does not answer how it got there.

## What to preserve

- A memory image of the target process
- The loaded-module list at the time of the alert
- The EDR/AV product logs for the host, if present

## When this is a false positive

Anti-cheat and DRM components patch their own process memory. They do it from their own process, with a signed image, at startup - the same telemetry but a stable parent.
