# Access to Browser Credential Stores and Wallet Vaults

- Rule: `4e7b1c93-2a58-4d61-9f04-8c6d2e1a7b50`
- Severity: medium
- ATT&CK: T1555.003, T1005
- Tactic: credential-access
- Status: **drafted from the rule, not worked against a live alert**

## What fired

A non-browser process reading or copying browser credential databases, DPAPI master keys, or cryptocurrency wallet vault files, or staging a copy of a database or archive out of a protected directory into Temp. The read half previously used Sysmon event 10, which is ProcessAccess and has no TargetFilename field, so that selection could never match; it is now Sysmon 11 FileCreate plus a registry-read branch for DPAPI master keys.

Event IDs in scope: 11, 12.

## Triage

Check these in order. The first one that is empty means the rule matched on a field the collector did not populate.

- `EventID`
- `TargetFilename`
- `TargetObject`
- `Image`

Identify the account and the process. A backup agent reading SAM as SYSTEM is ordinary; cmd.exe reading it from a user session is not.

## Containment

`revoke-session` - Reset the credential and invalidate live sessions. Assume the material left the host the moment it was read: a read is not a maybe.

Do not close out on the containment action alone. The entry being removed does not answer how it got there.

## What to preserve

- The alert's raw event, verbatim, before any field is normalised
- The host's clock offset from the collector
- The rule version that fired, from the rule's own id

## When this is a false positive

The behaviour this rule matches has legitimate causes on a managed host. Before closing, identify the parent process and whether the binary is signed; a signed path under `Program Files` with a service-account parent is the ordinary case.
