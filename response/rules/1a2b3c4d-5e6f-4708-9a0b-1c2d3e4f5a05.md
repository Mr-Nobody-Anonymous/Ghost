# CPU Information Enumeration Followed by Security Tool Tampering

- Rule: `1a2b3c4d-5e6f-4708-9a0b-1c2d3e4f5a05`
- Severity: medium
- ATT&CK: T1685, T1497
- Tactic: discovery
- Status: **drafted from the rule, not worked against a live alert**

## What fired

Correlation of a CPU-identifier read with a follow-on attempt to weaken a security component shortly afterwards from the same user context: a service or driver stopped, an AMSI provider removed, a Defender preference altered, or a signed security service touched. The original draft chained a Security 4663 registry read to a Sysmon 10 process access; that pairing cannot fire, because 4663 carries no ProcessId shared with Sysmon and Sysmon 10 reports a process image rather than a loaded module. Both members carry Computer, so that is the join key. This version keeps only events that a default Windows audit policy can actually produce.

Event IDs in scope: none.

This is a correlation rule. It fires when 2 underlying rule(s) reach None within 5m, grouped by Computer.

Underlying rules:

- `4663b1a0-0000-4000-8000-000000000001`
- `5e1c0f27-3a64-4b18-9d75-0c2f8a41b6e3`

Open the underlying alert before this one. A correlation alert with no visible member event is a gap in the underlying rule's collector, not a quiet incident.

## Triage

Check these in order. The first one that is empty means the rule matched on a field the collector did not populate.

- `Computer`

Enumeration is usually the quiet step before a loud one. Look for what the same process did next, not at the enumeration.

## Containment

`isolate-host` - Enumeration alone is not damage, so isolate rather than erase: the value of this alert is the next step it predicts, not the enumeration itself.

Do not close out on the containment action alone. The entry being removed does not answer how it got there.

## What to preserve

- A memory image of the target process
- The loaded-module list at the time of the alert
- The EDR/AV product logs for the host, if present

## When this is a false positive

Anti-cheat and DRM components patch their own process memory. They do it from their own process, with a signed image, at startup - the same telemetry but a stable parent.
