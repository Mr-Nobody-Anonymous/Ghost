# Scheduled Task Created at Logon by Unusual Parent

- Rule: `1a2b3c4d-5e6f-4708-9a0b-1c2d3e4f5a02`
- Severity: high
- ATT&CK: T1053.005
- Tactic: execution
- Status: **drafted from the rule, not worked against a live alert**

## What fired

schtasks /Create /SC ONLOGON invoked by a non-installer parent process.

Event IDs in scope: 1.

## Triage

Check these in order. The first one that is empty means the rule matched on a field the collector did not populate.

- `EventID`
- `Image`
- `CommandLine`
- `ParentImage`

Read the parent process before the command line. The command line tells you what ran; the parent tells you who chose it.

## Containment

`kill-process` - Stop the process by PID after capturing the image. Then check what its parent did, because the parent chose it.

Do not close out on the containment action alone. The entry being removed does not answer how it got there.

## What to preserve

- The scheduled task XML (`schtasks /query /xml`)
- The task's author and registration date
- The command the task runs, as stored, not as displayed

## When this is a false positive

Software updaters register scheduled tasks with SYSTEM context and a path under `Program Files`. Check the task's author and the signature of the binary it runs; a vendor task resolves to a signed path and a stable author.
