# Network fingerprint detections

Three low-cost, high-value detections for the beacon transport. All are
signature/detection content; none reproduce client behavior.

## 1. JA3 for a Python `ssl` ClientHello

Zeek `ssl.log` field `ja3`. Python's `ssl` module produces a distinctive ClientHello
(cipher order and extension set) that differs from browsers. Rule: alert when a
host with no known Python-based application emits that JA3 to a public IP on 443.

```
event ssl_client_hello(c: connection, version: count, record_version: count,
                       possible_ts: time, client_random: string, session_id: string,
                       ciphers: index_vec, comp: index_vec, ext: index_vec)
  {
  local ja3 = ja3_hash(c, version, ciphers, comp, ext);
  if ( ja3 in LAB_PYTHON_JA3_SET && ! is_known_python_host(c$id$orig_h) )
    NOTICE([$note=Python_TLS_ClientHello, $msg=fmt("JA3=%s", ja3), $conn=c]);
  }
```

Populate `LAB_PYTHON_JA3_SET` from a controlled lab host, not from production
traffic. Version changes alter the hash — pin the observation date.

## 2. Zeek x509 self-signed on 443

```
event x509_extension(c: connection, is_orig: bool, ext: string)
  { /* collect issuer == subject */ }

event connection_state_remove(c: connection)
  {
  if ( c$ssl?$cert && c$ssl$cert$issuer == c$ssl$cert$subject
       && c$id$resp_p == 443 && ! is_internal(c$id$resp_h) )
    NOTICE([$note=Self_Signed_443, $conn=c]);
  }
```

The design uses `CERT_NONE` on the client, so a self-signed server certificate is
expected. Legitimate internal appliances also use self-signed certs — scope by
destination and baseline first.

## 3. Suricata header pair

See `sigma/network/suricata_xid_xseq.rules`. The `X-Id`/`X-Seq` pair is the
strongest application-layer signal; the TLS fingerprints are fallbacks for when
headers are encrypted or not retained.
