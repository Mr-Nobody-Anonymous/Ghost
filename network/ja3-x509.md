# Network fingerprint detections

Three low-cost, high-value detections for the beacon transport. All are
signature/detection content; none reproduce client behavior.

## 1. JA3 for a Python `ssl` ClientHello

Zeek `ssl.log` field `ja3`. Python's `ssl` module produces a distinctive ClientHello
(cipher order and extension set) that differs from browsers. Rule: alert when a
host with no known Python-based application emits that JA3 to a public IP on 443.

```
# Pseudocode, not a Zeek script.
#
# The previous version of this block was fenced as Zeek while calling
# `ja3_hash()` and `is_known_python_host()` - neither exists in Zeek - and
# indexing `LAB_PYTHON_JA3_SET`, which was never defined. It looked runnable and
# would have failed on load. Zeek ships JA3 in ssl.log when ja3 support is
# enabled, so the detection is a *filter over a log*, not a script hook.

on ssl.log record where server_name is set and port == 443:
    if ja3 in <lab python JA3 set> and orig_h is not a known python host:
        alert "python TLS ClientHello from orig_h to server_name"

# Getting it working:
#   1. enable ja3 in the Zeek build (--enable-javascript is not enough;
#      ja3 needs the ja3 package or Zeek >= 6 with JA3 built in)
#   2. confirm `ja3` is populated at all: zeek-cut ja3 < ssl.log | sort -u | head
#   3. record the hash from a controlled lab host into the set below
```

The `ja3` value is a property of the *build*: a Python version upgrade can change
the extension set and therefore the hash. Pin the observation date and the Python
version with the value, or the set silently stops matching.

Populate the set from a controlled lab host, not from production traffic.

## 2. Zeek x509 self-signed on 443

```
# Pseudocode, not a Zeek script.
#
# `ssl_client_hello`/`connection_state_remove` with `c$ssl$cert` is the right
# shape, but `is_internal()` is a site function most deployments do not define,
# and a self-signed check needs the issuer/subject pair, which Zeek exposes in
# x509.log rather than on the connection record.

on x509.log record where port == 443:
    if certificate.issuer == certificate.subject and resp_h is not private:
        alert "self-signed certificate on 443 from <resp_h>"

# Simpler and version-independent: filter x509.log
#   zeek-cut id.resp_h certificate.subject certificate.issuer < x509.log \
#     | awk '$2 == $3' | sort | uniq -c | sort -rn | head
```

The design uses `CERT_NONE` on the client, so a self-signed server certificate is
expected. Legitimate internal appliances also use self-signed certs — scope by
destination and baseline first.

## 3. Suricata header pair

See `sigma/network/suricata_xid_xseq.rules`. The `X-Id`/`X-Seq` pair is the
strongest application-layer signal; the TLS fingerprints are fallbacks for when
headers are encrypted or not retained.
